# P6 bot services

`SqliteBotRegistry` requires an existing signed meta bot registration, current locally held bot key/placement, explicit owner configuration, and reviewed runtime evidence. Configuration is inactive by default; `qualify` also checks the real adapter's live `supports`. Operator/CLI execution is unavailable. The deterministic test provider's qualification does not qualify any paid provider or packaged reader build.

`BotAdmissionService.admit` accepts ordinary indexed delivery/replay, never snapshots. It verifies exact signatures, current human membership/steer/visibility, placement, confirmed applied meta, the delivery window and correlated clock measurement. Deduplication follows authorization and precedes the window. Admission commits execution, full ceiling, member rate, capacity, configuration/policy snapshot, compartment/output/thread/workspace binding and signed outbox receipt on one `NetDatabase`. Private receipt sealing uses a preallocated execution ID before SQL; rollback burns the nonce without exposing a receipt or running work.

Public thread triggers require the verified bounded same-space/authority ancestry to an active registered channel, indexed human trigger and current read proofs for the human and bot owner. The host authenticates each generated opening against its exact child binding. Private output from a public nested trigger remains denied until a separate private routing proof is qualified. Expired channel/private triggers produce only a signed marker on the indexed trigger stream, with no accepted binding, output creation or spend reservation.

Composition supplies a current host-confirmed meta head with monotonic confirmation timestamp and a fresh qualified clock sample. Output planning chooses the actual pre-created authenticated private stream, or a new public workstream. `MmsBotMaterializer.plannedIds` supplies deterministic backing-thread/workspace IDs. Its actual `ThreadDataStore.ensureExecutionThread` creates an isolated standalone thread; scratch data remains under that profile/thread with a durable ownership marker. Reader roots resolve only from an owner-selected local `ProjectManager` project ID. Chat has no project/Git context. Model execution never loads backing-thread transcripts or local Group state.

`BotExecutionService.start` persists running before the native adapter begins. Terminal state/accounting/context/receipt writes are atomic, and unknown provider usage remains reserved. Metadata/roster/private-control changes must call the corresponding reconciliation methods. Incompatible policy/definition/participant changes reject continuation; private publication checks the original visibility epoch and participant hash. A provider that does not prove quiescence retains capacity, and `stop` cannot acknowledge a drain while such slots remain. Process restart fences old effects and converts accepted to failed and running/waiting to uncertain; it does not retry models. Restart recovery touches only bot-admission rows, never Bridge RPC rows.

Terminal host rejection of the exact accepted receipt fences model starts, cancels the active controller, suppresses later publication and fails already queued dependent receipts. A provider already dispatched still reconciles proven terminal usage; unknown usage stays reserved. `close` removes observers and drains cancelled controllers. Pending/unknown acceptance retains the existing queued-before-effects admission semantics. Outbox transport must preserve durable enqueue order and stop a stream behind an ambiguous acknowledgement.

Generic terminal receipts that cannot safely be signed during cold/revoked/unreadable state remain in `net_bot_terminal_pending`. `flushTerminalPending` publishes only generic terminal metadata after fresh authorization returns, without rerunning effects or settling twice. Permanently revoked/changed audience rows remain local audit evidence. Oversized inline result publication fails closed rather than silently emitting an oversized envelope; a scoped bot attachment publisher remains a composition extension.

`BotPermissionService.port` requests exact action approvals in an authenticated private stream containing exactly owner/requester/bot. It waits for the execution acceptance ACK before publishing on the permission stream; ambiguous acceptance blocks publication, terminal rejection refuses it, and a bounded 30-second ACK wait/abort creates no request journal. `grant` verifies the independently bot-signed original request and human trigger, then journals an independently owner-node-signed sealed grant idempotently. `receive` verifies both signatures, exact original request hash, action/profile/audience binding and expiry. `consume` commits single-use immediately before returning to effect dispatch and rejects active outer transactions. The approved callback converts the authoritative host expiry to local wall time; every grant/consume still checks the fresh authoritative host clock. Root transport must deliver the original request before grants.

`BotRecordAuthorization` supplies real host current-policy/signature registration and output gates. Private bindings must retain immutable visibility epoch/participant hash. PrivateService `canBotWrite` and `validateExecutionReferences` must both delegate to this concrete gate: only exact execution/trigger/parent/current-audience references waive same-stream locality, and permission/expired/unrelated event types receive no waiver. Public-trigger private output contains exactly owner/requester/bot; private-trigger output remains on its original stream. Historical reads require independently verified historical bot/member/steer evidence and verified retained private controls (`historyState`); absent proof denies. Concrete `MetaProjection.botAt`/`canSteerAt` use generation-scoped validated transition history, including bot tombstones and owner removal after the original registration. Private snapshot recipient validation must bind its `botAt` option to that concrete accessor, never the current bot registry. Pre-upgrade missing evidence remains denied until `rebuildBotHistory(space)` reconstructs it through a bounded, signed full-meta snapshot; it does not infer history from current entities. Actual TLS tests cover public/private expiry and exact private reference rejection. The host atomically registers private acceptance bindings from indexed human triggers and the trusted current `authorizationAudience` before this verifier admits subsequent output or permission requests; a generic true callback is insufficient. Private snapshot composition must delegate `verifyBotRecord` to `verifyHistory(record, descriptor, verifiedControl)`: the isolated validator authenticates each controlling signed audience before the callback, then adopts keys/control and cursor only at commit. Normal sealed bot history uses the adopted retained control and the same immutable proof. Known bot run receipts and permission requests require a bot author; grants/denials require a human node author even when their contents are sealed. Focused adversarial tests cover absent proof, altered immutable audience, a genuinely signed removal control, and human-signed typed records; the history replica test is opaque and does not qualify participant plaintext replay.

`BotPresenceService` emits bot-signed monotonic counters and fixed `workingPrivate` without private text. `BotPresenceReceiver` durably rejects replay, checks current signed placement, and reports reconnecting at45s/offline at90s; a restart retains counters but starts display offline. Root must negotiate presence only with this actual verifier and send through authenticated sessions.

`BotProfileService` composes these actual services with the native MMS loop and materializer. Its bounded ordinary-delivery scheduler never admits snapshots, requires a fresh actual remote `metaHead` plus qualified clock sample (or the local authority's own current head/clock), waits for a real acceptance ACK before model calls, and retains unknown acceptance until the same journal row is acknowledged. Restart converts earlier accepted/running work without model retries. Root supplies original-byte checked `appendSigned` and FIFO `flush`; those ports must use actual authority/client transport. Local executor output bindings and independently verified client history bindings are separate from the host's authoritative accepted ledger. Host gates resolve only the authority ledger. Client history adoption requires signed indexed openings, original human triggers, exact historical actors/policy and authenticated private controls. Native adapter keys each capture an immutable trusted definition and independent qualification/invalidation scope; all production native profiles default inactive. Configuring or qualifying through a DTO cannot create provider billing or platform evidence. Reader packaging/provider qualification and central MMS/CLI wiring remain root composition work.
