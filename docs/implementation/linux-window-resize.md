# Linux window resizing

I added six-pixel resize borders and larger corner targets to the Linux main and Agents & Tasks windows. These transparent handles sit above titlebar drag regions and dialogs, while leaving interior content clickable. They disappear when the main window is maximized. The native controller keeps each window's gesture independent, anchors the opposite edges, enforces minimum/maximum sizes, and ends gestures on pointer loss, blur, navigation or window state changes. Resize IPC admits only the owning main frame of those two app windows. Native embedded browser views leave the resize border uncovered.

Electron documents that [transparent windows do not support ordinary resizing](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles), and [Wayland restricts programmatic window positioning and resizing](https://www.electronjs.org/docs/latest/api/browser-window). I retain the alpha surfaces and rounded clipping and use client-side resize handles. Linux GUI launchers select X11/Xwayland when a DISPLAY is available, unless an explicit ozone-platform argument was supplied. The packaged GUI relaunches once with that argument before creating windows or connecting to the daemon. The backend must be selected at process startup so GTK and Chromium use the same display. Explicit native Wayland and display-less launches remain available, with those platform limitations. Headless CLI launch, Windows and macOS retain their existing backend and window behavior.

I verified focused controller/startup tests and a native Electron fixture using the actual resize component, production preload and IPC registration. Electron supplies real PointerEvents and pointer capture; the fixture injects only the cursor position rather than moving the physical mouse. It checks all eight resize directions, opposite-edge anchors, the auxiliary window, embedded browser bounds, popup denial, maximize visibility and retained alpha after resizing. Node/web typechecks and focused source lint passed. I did not run the full suite. Existing Mousse processes need a restart to load this native-window change.
