# Execution and browser contract foundation

Root-authored C4/C6 initial modules are in `src/shared/execution`, `src/shared/browser`, `src/mms/execution`, and `src/browser-worker/observation`. These are real validated contracts and small services; they do not constitute an enabled browser executor or a durable workflow engine.

`ExecutionContext` follows architecture section3.3. Validated daemon ingress assigns profile/thread/turn/actor/policy/cancellation identity. `ExecutionPolicyService` creates immutable hashed snapshots by intersecting installation authority with narrower profile/project/run/agent/node restrictions. Absent installation tool grants deny tool access. Lower layers cannot add tools, capabilities or effect classes; any layer can add an approval requirement. Unknown effects always require approval if otherwise allowed. Authorization returns allowed/denied/approval-required. It does not grant approval or silently execute unattended work. W02 must durably store and resolve approvals against exact request digest, actor, policy snapshot and pinned assets; policy evaluation alone is not an approval implementation.

`CancellationRegistry` owns AbortControllers by profile; serialized contexts carry opaque cancellation IDs. Child cancellation propagates from its parent, including a child created after parent cancellation. Releasing a context cancels descendants and detaches its parent listener. W02/M01 must resolve and pass those signals to actual tools/processes; the registry does not stop operating-system processes by itself.

`BrowserObservation`, typed action/request/result, session lifecycle and private worker DTOs are shared. Action validation rejects arbitrary code/selectors, unknown keys, unsupported schemes, embedded URL credentials, unbounded timeouts and raw upload paths. Uploads use authorized artifact IDs. Navigation URL syntax validation is not origin authorization: MMS policy and worker navigation enforcement remain mandatory.

`BrowserReferenceStore` mints opaque references only for observed backend DOM identities. Scope includes profile/session/process generation/tab/document/observation; navigation invalidates tab refs. The bounded store retains at most8 observations of1000 elements by default. B02/B03 must validate live frame/DOM attachment and fingerprints before dispatch; reference lookup alone does not prove actionability.

`imagePointToViewport` transforms exact screenshot pixels through per-axis capture scale and crop origin. It never derives image scale from monitor DPI or adds page scroll to viewport input coordinates. It rejects invalid geometry and image/viewport bounds. B02 must capture and validate the actual metadata, including frame transforms; M03 adapters convert their provider-specific normalized coordinates into this common image-pixel space.
