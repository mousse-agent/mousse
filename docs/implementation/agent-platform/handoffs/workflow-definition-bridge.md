# Workflow definition app bridge

Root connects the reviewed W01 registry to the canvas definitions client through 13 profile-bound domain methods. Register `registerWorkflowDefinitionMethods(domains, registryForProfile)` before server seal and advertise `workflows.definitions.v1` only when the profile registry exists. Exact names are exported by `src/shared/workflowPlatform.ts`.

`createWorkflowDefinitionsClient` in renderer services structurally matches the canvas `WorkflowDefinitionsClient` contract. It supports list/get/create, draft saves with optimistic hashes, publish, archive, duplicate, import/export, draft/publish validation, revision history and restoring an old revision into a draft. Restoring never moves the current published head. Archive hides an item from the default list; `archived: true` includes it. Project-discovered workflows are listed without their private root paths; editing project definitions still needs a dedicated read-only/import path before it can be advertised as supported.

The daemon selects a registry from the admitted connection and rejects a mismatched claimed profile, foreign/malformed IDs, missing optimistic hashes and direct path fields. Imports cannot overwrite existing IDs/slugs; `conflict: rename` explicitly creates a new copy. Unknown node types remain persisted and diagnosed by the existing compiler. Publish retains compiler validation and immutable byte checks.

Workflow binary assets now cross JSON with explicit `utf8`/`base64` encodings (`src/shared/workflows/wire.ts`). Sending raw `Uint8Array` through JSON would otherwise corrupt assets. The daemon validates keys, encoding, paths (including case collisions/reserved manifests), and optional SHA-256 before registry writes. Scripts remain data during import. Requests retain the existing protocol text limit, and document/export/list responses reject above 3 MiB; a future streaming package transfer is required for larger existing bundles rather than silently dropping assets.

The registry adds `listRevisions`, reading only validated hash identities and verifying each immutable revision. It uses the stored revision lock's publish timestamp, preserving historical metadata separately from the current head.

Verification: 18 tests in `platformWorkflowDomains` and `platformWorkflowRegistry`, plus full node/web typecheck. New tests run the real renderer adapter through JSON serialization into real domain/registry services: edit/publish/history/restore, stale-save conflicts, exact binary roundtrip, asset escape/digest refusal, profile isolation, duplicate import handling, and archive visibility. These are service/transport adapter checks; canvas mounting, production IPC registration, run methods, slash/CLI ingress and real execution adapters remain separate required work.
