## Production behavior

`MmsProfilePlatform` owns one `MmsWorkflowCoordinator` per profile. `MousseMainService` registers the ten workflow run methods, and GUI/CLI clients negotiate `workflowRuns.v1`. The preload request allowlist includes those methods. `AgentsWorkspace` supplies the real request-backed execution client to the existing workflow editor and library Run dialog.

The coordinator validates the published revision or exact saved draft, schema, executor availability, and owning project/thread before creating a run. A durable admission record stores the chosen thread ID, immutable revision/input, execution actor, source, and policy. The client request UUID is reused across transport failure. Retries after reconnection, daemon reconstruction, or later publication return the same run/thread; changed input under the same identity is rejected. If an accepted run's thread was deleted, replay rejects instead of recreating it. `ThreadDataStore.ensureExecutionThread` repairs partial initialization without overwriting existing messages or duplicating the standalone index.

The composed runtime supports pure/structural nodes, durable input/approval/timer waits, artifacts, and approved trusted-local scripts. Workspace file inputs are read from the owning project through bounded regular-file reads, containment and symlink checks, handle identity checks, and a second ownership check. Root timers wake durable root waits without an open renderer and retry temporary control-lease contention. Profile shutdown cancels timers/subscriptions and stops runtime drivers. Agent/tool/MCP/Skill/browser adapters have an explicit trusted configuration seam and are not yet composed here; unavailable adapters fail admission rather than reporting fabricated execution.

Run views remain bounded with explicit truncation notices; they now include the durable journal sequence. The desktop client polls without overlap, reports connection failures, stops terminal polling, ignores late unsubscribed results, and prevents older results replacing newer control responses. The panel prevents duplicate clicks and retains its start UUID after a failed transport. Library quick runs fetch the actual published input schema, even when the draft differs. Object/array inputs preserve incomplete JSON visibly and disable Run until corrected; enum values retain their JSON types. Ask-user forms support structured answers. Cancellation remains available for durable waiting/interrupted states.

Visual verification exposed a canvas defect missed by earlier rectangle-only checks: definition updates dropped React Flow's measured node dimensions and made nodes invisible. Updates now preserve measurements, published read-only graphs accept layout measurement changes, and resize recovery fits graphs when all nodes leave the canvas. The fixture checks actual visibility, horizontal/vertical intersection, and rendered connection paths.

- Eight existing real-engine run-domain tests pass. Four new client transport tests cover stable request identity, wrong-profile/fixture-response rejection, out-of-order results, polling failure/retry, terminal stop and late unsubscribe.

Desktop and narrow screenshots were inspected. This fixture uses an explicitly labeled controlled execution client; the separate framed MMS test proves host execution.
