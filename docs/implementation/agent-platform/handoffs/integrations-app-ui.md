# Integrations app UI and lifecycle form repairs

Root implementation, September 11, 2026. Baseline `c67f3e99cde5b1d8726e811200fde1c9e6a4a099`; this commit contains the reviewed-by-root candidate. Sol review remains required.

Settings now includes a **Skills & MCP** destination with a profile/project selector, searchable catalogs, direct Add Skill, Upload, and Add MCP actions. It uses the production `window.mousse.platformRequest` transport through `createIntegrationPlatformClient`. Existing skill model defaults and tool access controls remain available. Settings personal state unmounts at the profile boundary, and leaving an integration form for another settings section, closing Settings, or changing scope consults its dirty guard. Profile changes consult all registered editor guards.

The original isolated UI candidate `2132ca5` had production contract defects. MCP update spread a create payload containing the rejected `scope` field, saved masked secret maps, did not expose OAuth replacement intent, and trimmed process arguments. OAuth failures could display verified success, and a shared busy flag disabled cancellation. The replacement form reads the latest saved revision, uses separate typed create/update builders, preserves omitted environment/header/auth maps, supports explicit whole-map replacement, round-trips JSON argv (including empty and spaced strings), and allows an empty cwd to clear the optional override. Connection tests and OAuth feedback are distinct. Pending OAuth is cancellable and disposed with the originating dialog; late callbacks cannot update a different profile's UI.

Skill creation and upload retain their drafts while switching modes. The directory picker has the actual Chromium `webkitdirectory` attribute. File counts, sizes and paths are checked before reading; ZIP transfer size is bounded. Nested paths and exact source bytes survive packaging. Editing loads source and revision together rather than trusting a stale catalog row; conflicts retain the user's source. Export/testing requires saved source. Enable/archive cannot silently discard a draft. All asynchronous completions, including downloads, are fenced by the mounted profile/project/client identity.

The new forms exposed a ResizeObserver feedback loop in the shared Markdown editor. `MarkdownDocumentEditor` now owns an observer that schedules deduplicated layout in `requestAnimationFrame` and disconnects/cancels on disposal. It no longer uses Monaco's synchronous automatic layout. Both integration and Agent Editor fixtures exercise physical Monaco typing and Source/Preview preservation after this change. The Liquid Glass Orb was not modified.

## Qualification boundaries

The renderer fixture intentionally uses an isolated controllable client to exercise cancellation, revision and error UI states. It is not evidence of production OAuth or a complete packaged Settings journey. Real framed-domain tests supply the separate backend contract evidence. Sol's production preload/window/profile fixture and later full-app qualification remain necessary.

Project-managed integration ownership and stable identities still need I04: profiles selecting the same filesystem repository currently target shared `.mousse` project paths. The assigned integration worker is moving managed writes to profile-owned project storage and auditing explicit trusted external discovery, grants, secrets and native/CLI materialization. Live OAuth interoperability, callback/refresh behavior, complete native/CLI capability coverage, skill Test execution, full App route qualification, and packaged acceptance are still open. No release gate is closed by this UI commit alone.
