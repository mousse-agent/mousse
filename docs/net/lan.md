# Automatic LAN connections

Enabled, unlocked Net profiles listen for paired devices on an ephemeral IPv4 TCP port and discover each other using UDP multicast `239.255.77.77:47777` (TTL 1). This works without the hosted relay, including after both computers restart. The configured `direct` listener remains separate: disabling it withdraws its published routes, while automatic LAN connections remain available. Disabling Net stops both.

Every five seconds each profile sends a fixed-size advertisement for up to 64 peers in its current signed roster. Each advertisement is AES-256-GCM encrypted with a directional key derived with HKDF-SHA256 from the devices' X25519 agreement keys and the sender's node id. The packet contains only a timestamp, listening port and random padding. It exposes no account, device id, device name or route in plaintext. Nearby observers can still observe traffic timing and source addresses.

Authenticated hints expire after 30 seconds, require clocks within 30 seconds, and use the UDP source address rather than a supplied hostname. Up to eight interface addresses per peer are retained so VPN and virtual interfaces do not replace a usable WiFi address. Memberships refresh when interfaces change; a failed UDP socket is retried on the next tick. Discovery processing is bounded to 128 candidate packets per five seconds and 64 peer keys. This bounds work but does not prevent local denial of service.

Hints stay in memory and are never added to signed or cloud-published routes. They are tried before existing routes. They do not authenticate a session: the existing pinned TLS certificate, signed hello, current delegation and revocation checks still apply. The TCP listener uses the existing preauthentication connection, byte and deadline limits. Revoked peers are removed from discovery on its next tick. A lapsed delegation can still yield a hint so the existing authenticated hello can recover a renewed roster; session authentication enforces the current roster independently.

Both computers need a build with LAN discovery. IPv6-only networks, WiFi client isolation, blocked multicast and host firewalls that reject the listener cannot use this path. Existing relay and manually configured routes remain fallbacks. Initial pairing still needs an existing enrollment route. Automatic Tailscale discovery and a path indicator in Devices are separate work tracked in #379.
